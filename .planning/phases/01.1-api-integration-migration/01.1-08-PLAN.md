<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/api/dashboard/teams/{slug}/domains*` | Firebase bearer token crosses here; the backend enforces team membership via `require_team_member` |
| user-supplied domain string -> backend | An untrusted hostname crosses here and is later used in DNS lookups server-side |
| backend `status` field -> rendered badge | A security-relevant assertion ("this domain is verified") crosses into presentation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.1-05 | Spoofing | verification status rendered in `domain-row.tsx` | medium | mitigate | The badge variant is derived solely from the server's `status` field through an exhaustive switch; the frontend never computes, caches, or optimistically sets "verified". Prohibited explicitly. A client-computable verified state would reduce a real DNS ownership proof to decoration. |
| T-01.1-24 | Elevation of Privilege | team-scoped domain mutations | low | transfer | Authorization is entirely backend-owned (`get_current_user` + `require_team_member` + owner-role checks in `domains.py`). Per RESEARCH.md's Security Domain V4 note, the frontend must trust the backend's 403/404 rather than duplicate the check client-side. |
| T-01.1-25 | Information Disclosure | `verification_token` displayed in the add form | low | accept | The TXT token is a proof-of-ownership nonce the user must publish in public DNS by design; displaying it to the team member who created it discloses nothing that will not shortly be world-readable. |
| T-01.1-26 | Tampering | user-supplied domain string rendered in a row and in a `confirm()` | low | mitigate | Rendered as a React text child (escaped) and inside a native `confirm()` string, which is not an HTML context. `truncate` bounds visual overflow. Format validation is backend-owned via `AddDomainInput`'s regex; the frontend mirrors the bound for UX only. |
| T-01.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing; `label` was installed and audited in plan 01.1-03. `git diff --stat package.json package-lock.json` must be empty; if it is not, HALT. |
</threat_model>
