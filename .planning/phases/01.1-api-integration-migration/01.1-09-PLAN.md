<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> `POST /api/requests/{slug}/upload` | Fully unauthenticated file upload — the widest-open surface this phase exposes |
| owner browser -> `/api/dashboard/requests*` | Firebase bearer token crosses here; ownership enforced backend-side |
| owner-authored title/description -> anonymous viewer | Content authored by one user renders to arbitrary third parties |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.1-04 | Denial of Service | anonymous upload endpoint | medium | transfer | Bounds are backend-enforced: `max_files`, `max_file_size_mb`, `expires_at`, and `is_active` are all validated server-side, and `dropitx-api` applies its own upload rate limiting. The frontend mirrors `max_files`/`max_file_size_mb` in the dropzone config for UX only and must not treat those client bounds as a control. |
| T-01.1-27 | Information Disclosure | Firebase ID token sent to a public endpoint | medium | mitigate | Prohibited outright and enforced by the acceptance criterion `grep -c 'authFetch'` returning 0 on the public page. The page also must not import `components/upload-dropzone.tsx`, which hardcodes `authFetch` — enforced by its own grep criterion. |
| T-01.1-28 | Tampering | owner-authored title and description rendered to anonymous visitors | medium | mitigate | Rendered as React text children (escaped by default); no `dangerouslySetInnerHTML` is introduced; `line-clamp` bounds overflow. Length bounds are backend-enforced (`title` max 200, `description` max 2000). |
| T-01.1-29 | Spoofing | client-side expiry determination | medium | mitigate | The open/closed branch reads only the server-computed `is_expired` field, never a client comparison of `expires_at` against the local clock. A client-side date check would offer an upload form for a request the owner had deliberately deactivated, and would be trivially defeated by a skewed system clock. |
| T-01.1-30 | Information Disclosure | uploader-supplied name and email | low | accept | Collected only when the owner set `require_name`/`require_email`, transmitted over TLS to the endpoint that requested them, and stored backend-side. No new frontend persistence is introduced; the fields are not written to localStorage or logs. |
| T-01.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing — `react-dropzone@^15.0.0` and every UI primitive used are already dependencies. `git diff --stat package.json package-lock.json` must be empty; if it is not, HALT. |
</threat_model>
